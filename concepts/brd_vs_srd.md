# BRD vs SRD — 비즈니스 요구사항 vs 시스템 요구사항

> 검증: `~/Downloads/Ex1_Business_Reqmnt.pdf`, `~/Downloads/Ex2_System_Reqmnt.pdf` — 일치
> 예시 프로젝트: 자율 이동 로봇(AMR) 보안 시스템

## 한 줄 요약

- **BRD (Business Requirements Document)**: *무엇을, 왜* 만들 것인가 — 비즈니스 관점
- **SRD (System Requirements Document)**: *어떻게* 만들 것인가 — 기술 구현 관점

SRD는 BRD를 **구체화한 후속 문서**다. BRD는 "성공 조건"을 정의하고, SRD는 "그 조건을 만족시키는 시스템 구성"을 정의한다.

---

## 목적·작성 시점 비교

| 구분 | BRD | SRD |
|------|-----|-----|
| 핵심 질문 | Why / What | How |
| 독자 | 프로젝트 오너, 이해관계자, 의사결정자 | 개발자, 시스템 엔지니어, 아키텍트 |
| 작성 시점 | 프로젝트 착수 단계 | 설계 단계 (BRD 이후) |
| 추상화 수준 | 기술 비종속적, 솔루션-중립 | 기술 종속적, 구체적 사양 |
| 변경 빈도 | 낮음 (비즈니스 목표가 바뀔 때) | 높음 (기술 선택·아키텍처 변경 시) |

---

## 같은 요구를 어떻게 다르게 표현하는가

| 요구 영역 | BRD 표현 | SRD 표현 |
|-----------|----------|----------|
| 로봇 플랫폼 | "AMR 하드웨어" (벤더 무관) | TurtleBot3 + Jetson-Orin, Ubuntu 22.04 |
| 감시 | "고해상도 비디오/오디오, 360°" | USB 카메라 + LiDAR + 초음파, OpenCV + YOLO |
| 통신 보안 | "종단 간 암호화" | TLS 1.3 + AES-256 + WPA3 |
| 네트워크 | "안전한 통신 프로토콜" | Wi-Fi 6, 4G/5G 폴백, 1 Mbps/AMR |
| 알림 | "SMS, 이메일, 인앱" | Flask 백엔드 + 푸시 + SMS |
| 저장 | "장기 저장은 범위 밖" | 로컬 48h, 서버 30일, 월별 아카이브 1년 |
| 위협 탐지 | "컴퓨터 비전으로 무단 접근 감지" | AMR 로컬 처리 → 서버 집계로 오탐 감소 |
| 알림 지연 | "1초 이내" (성공 기준) | End-to-end < 1s + Wi-Fi 6 + 엣지 처리 (구현 수단) |

## 고유 섹션

### BRD에만 존재
- 비즈니스 목표 (Why)
- 프로젝트 범위 (In Scope / Out of Scope)
- 위험-완화조치 (Risk-Mitigation)
- 예산·일정 제약
- 이해관계자·승인자

### SRD에만 존재
- SW 패키지 목록 (Python3 / ROS2 / OpenCV / YOLO / Flask / SQLite3)
- HW 사양 (프로세서, 센서 종류, 배터리 수명)
- 데이터 처리 아키텍처 (엣지-서버 분리, 보관 정책)
- Failover·이중화 메커니즘
- 네트워크 프로토콜·암호화 표준

---

## 두 문서의 관계

```
BRD ──정의──> "1초 이내 실시간 알림" (4.4 Performance)
                       │
                       ▼ 구체화
SRD ──구현──> Wi-Fi 6 (5.1) + 로컬 비디오 처리 (6.1)
              + End-to-end latency < 1s (7.3)
```

- BRD의 한 요구사항이 SRD에서는 여러 기술 요소의 조합으로 풀린다.
- BRD가 변경되면 SRD의 영향 범위를 역추적해야 한다 (요구사항 추적성).

---

## 실무 팁

- 신규 프로젝트 착수 시: **BRD 먼저, SRD는 BRD 합의 이후** 작성.
- BRD에 기술 스택(예: "TurtleBot3 사용")이 섞이면 솔루션을 미리 가두게 된다 — 가능한 한 분리.
- 두 문서 모두 "수락 기준(Acceptance Criteria)" 섹션을 갖되, BRD는 비즈니스 KPI, SRD는 검증 가능한 기술 지표로 작성.
